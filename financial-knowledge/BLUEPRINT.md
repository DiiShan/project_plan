<a id="vision"></a>

## 终局与定位

终局可以用一句话钉住：把全市场个股财报，变成一套证据可追溯、能按公告时点回放历史、并能提出、检验、淘汰假设的投资研究系统。它要能回答「根据当时已经公开的信息，这条判断成不成立、什么情况下会失效」，而不是把财报扔进对话里，生成一份读起来通顺的摘要。

财报里既有财务数据，也有公司与行业描述。系统要做的，是把这些材料整理成可核对的事实、关系与经营变化，再提出可检验的假设——而不是把模型编出的逻辑直接当成规律。

所谓「自我演进」，指的是研究流程持续迭代：提出假设、寻找支持与反例、用当时可获得的信息回放检验、保留失败、把过时结论版本化淘汰。这不是模型自动改写奖励、风控、权限或评价口径，也不是让模型在全部资料上无约束地自我训练。知识更新指研究结论的更新与淘汰，不等于模型自行再训练。若把这种工作称作 Auto Search，它更接近带预算的自动化研究，而不是无限的网上搜索。

| 这是什么 | 这不是什么 |
|---|---|
| 研究流程可迭代：假设、反证、回放、入库、淘汰 | 不是聊天式摘要机，也不是自动下单引擎 |
| 每条结论都能追溯到原文与公告时点 | 不是模型自行改写目标、奖励或风控口径 |
| 失败假设也保留，避免重复发现假规律 | 不是对全部财报无约束地自由发挥 |

<a id="questions"></a>

## 要回答的研究问题

系统面向六类问题。前五项回答「经营上可能发生什么」；第六项才回答「这一信息是否还没被股价反映、对交易是否有增量价值」。两者必须分开记账：经营预测成立，不等于股价仍有投资价值。

| 编号 | 问题 | 要看清什么 |
|---|---|---|
| 01 | 经营变化 | 订单、库存、应收、合同负债、扩产、价格与费用，在财报中如何出现、如何逐期演变。 |
| 02 | 真实同类与共同暴露 | 不只按官方行业，还按共同客户类型、原材料、终端需求和商业模式分组。 |
| 03 | 产业链传导 | 上游扩产、中游涨价、下游需求变化，谁先谁后、时滞多长、有哪些反例。 |
| 04 | 财务质量与叙事一致性 | 管理层描述是否与数据一致；增长是否伴随现金、减值或关联交易异常。 |
| 05 | 周期拐点 | 景气、价格、产能周期的转折，能否在当时信息下被识别，而不是事后标注。 |
| 06 | 定价是否已经反映 | 即使经营变化为真，也要单独检验这一信息是否已被股价反映。 |

<a id="methods"></a>

## 方法如何递进

下面五步是方法加码的顺序。图数据库、向量库和长文本模型都不是第一版的先决条件。

1. **检索加结构化规则。** 先把可计算的财务关系做对。单位换算、合并口径和对账由程序完成，不让模型充当计算器。
2. **聚类与多标签动态分组。** 在证据之上形成可解释的分组，并保存 as-of 成员快照，便于历史回放。
3. **可解释特征。** 特征要能指出它来自哪类事实或暴露，而不是一个无法解释的分数。
4. **有设计的因果研究。** 没有识别策略时，只报告相关与时滞。单凭财报叙述不能证明因果。相关不等于因果；要谈因果，就在识别策略中控制混杂。
5. **可选的模型优化。** 仅用于检索或分类等辅助环节。图数据库和向量库不是先决条件；第一版用 DuckDB、本地文件和索引即可起步。本项不是已经接好的模型服务。

<a id="validation"></a>

## 验证与风控

### Point-in-time 与污染防控

- 回放使用公告可获得时间，不用录入时间冒充。
- 修订版本不能污染更早的判断。
- 若以后训练模型，训练样本不得含未来信息，并在结果中提示污染风险。这里不表示训练已经开始。

### 样本与成分

- 处理幸存者偏差和行业成分变化，优先使用当时的成分与存续公司。
- 跨公司、跨行业、跨时间做样本外检验；报告重叠事件与独立样本数。

### 质量与多重检验

- 数量、单位、币种、合并口径必须对账；抽取结果要对照原文做人工抽检。
- 用 FDR 或事先规定的假设试验预算控制多重检验，禁止事后只展示好看的结果。

证据不足时明确说「无法判断」，不编结论，也不用空洞的高置信度掩饰。

<a id="boundary"></a>

## 研究与交易的边界

研究意见，不是交易指令。

产出是研究台账、观察清单和风险提示。任何下单或调仓都须人工审批，系统不自动下单，也不承诺收益。与现有账户规则的接口保持不变：A 股只做多；配置仓不使用衍生品；股指期权仅限 IO/MO 价差，不做 A 股 ETF 期权。这些是使用边界，不构成本蓝图的研究主体。

<a id="examples"></a>

## 演示用假设样例

以下三个样例都是纯演示，不是真实发现。它们只展示一条假设应该怎么写：命题、证据链、反例、检验设计与数据缺口。未做任何回测，也不编造收益数字。本轮没有本地盘点，也没有规律发现。

<a id="example-a"></a>

### 演示 A：扩产到现金流

命题：公司披露重大扩产或在建工程显著增加后，若项目按期转固且产品未被价格或销量抵消，则在建设高峰后的若干报告期内，收入增长应逐步伴随经营现金流改善。若收入增加而经营现金流持续恶化、应收或库存异常上升，则假设在该公司、该周期失效。

证据链：扩产或资本开支的披露原文 → 在建工程与资本开支变化（结构化数据） → 转固或产能相关表述 → 收入与毛利 → 应收、库存、经营现金流。每一环都须有 loc 与 available_at。

反例与检验：行业已经供给过剩；建设周期长于预期；产品降价；确认收入但回款差；关联交易或一次性项目。检验时先预注册滞后期与样本规则，按时间切割，比较「有扩产披露」与对照样本在财务指标上的差异分布，不把相关当因果。若没有项目完工时点或产能数据，只报告证据不足，不编造进度。

数据缺口：许多公司不披露可比产能与完工时点；扩产公告与定期报告需对齐版本；价格与销量常常只有定性描述。

<a id="example-b"></a>

### 演示 B：合同负债或订单到营收

命题：合同负债或已披露的在手订单出现有业务含义的上升后，在履约周期稳定的前提下，随后 1–2 个报告期收入应有可核对的释放。若合同负债下降只来自会计重分类、退单或政策变更，则不能视为需求改善。

证据链：合同负债及注释、订单或预收款披露、收入确认政策、同期收入与递延类科目、可能的退货或减值。

反例与检验：一次性预收款、履约周期变长、大额取消、渠道压货体现在其他科目、口径调整。需做会计政策与重分类检查，跨行业做样本外验证，并报告独立事件数——同一公司连续多期可能不是独立样本。

数据缺口：在手订单口径不统一，不少公司没有标准化订单数据；合同负债覆盖不全，不能把缺失当成零。

<a id="example-c"></a>

### 演示 C：跨行业原料敏感群体

命题：成本对同一关键原料暴露较高的公司，即使分属不同官方行业，在原料价格冲击后，毛利率可能出现方向相似、滞后期受库存与合同条款影响的变化。若公司具备明确的价格传导、保值或一体化能力，则不应被放进同一「高敏感」组。

证据链：成本结构或原料名称的原文（未披露则保持未知，不得补全客户或供应商身份）、毛利率、库存周转、若有的定价表述，以及可对齐时点的原料价格指数。

反例与检验：提价顺利传导、套期保值、产品结构变化、同一官方行业内其实暴露不同。分组必须可按 as-of 回放；冲击日之后才观测到的信息，不能用来构造冲击前的分组。

数据缺口：原料名称常被写成「主要原材料」；数量与单位需要对账；外部价格指数要能与报告期对齐，且自带可用时点。
