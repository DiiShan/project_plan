## 两轮结论如何衔接

第二轮对第一阶段作了明确收敛：第一阶段不是代码骨架、静态页面或仅验证能打开窗口，而是可实际使用的“项目库＋下一步工作台”。

第一阶段必须完成的闭环：

> 记录想法 → 登记项目 → 中文搜索找回 → 安排具体下一步 → 关闭重开后继续工作 → 备份并成功恢复。

第一阶段包括必要的技术与打包验证，以及原总体规划中的管理 MVP。技术验证是开发过程，不是第一阶段的最终交付。

**发生表述差异时，第一阶段的范围、开发批次和完成标准，以第二轮《第一阶段实施方案》为准。** 总体规划中的 P0、P1 等编号保留为原始路线参考，不应与第二轮的“第一阶段”和“六个开发批次”机械等同。

特别是：总体规划末尾“下一轮只做 P0-A”的提示属于第一轮历史建议；当前首个开发批次，应采用第二轮规定的“可双击启动、可记录和修改一句想法、重启后仍保存”的小版本，不止是静态窗口。总体规划中的执行器风险验证延后到实际进入运行能力开发前，不据此把运行功能塞入当前阶段。

## 已确定的主要取舍

- 主方案：C# / .NET 10 LTS / WPF / SQLite；不因偏好擅自换框架。
- Windows 本地优先，管理数据与程序安装目录、原项目源码目录分离。
- 第一阶段不包含程序执行、自动调度、自动扫描、对话解析、AI 接口、Outlook、手机同步。
- 不默认上传、遥测、联网摘要；本次仅上传规划结论，不包含个人项目源码、本地真实路径、凭据或聊天原始记录。
- 核心管理不依赖 AI；后续执行能力必须经过明确授权和单独验收。
- 规划中的性能数字是待测试的目标，不是已经测得的结果。
