# 第一阶段实施方案：可日常使用的“项目库＋下一步工作台”

> 第二轮讨论结论归档。归档日期：2026-10-27。当前只归档规划，尚未开始开发。
>
> 本文是当前第一阶段范围、开发批次和验收标准的直接依据。总体架构、安全边界与后续路线参见[总体规划](01-overall-plan.md)；两轮方案的衔接说明参见[仓库首页](../README.md)。
>
> 第一阶段包含必要的技术与打包验证，以及总体规划中的管理 MVP。技术验证只是过程，不是本阶段的最终交付。本文第一批“可启动、可保存的最小应用”优先于第一轮末尾仅做 P0-A 窗口原型的历史建议。

## 建议的第一阶段：做一个能日常使用的“项目库＋下一步工作台”

**第一阶段结束时，你应该已经可以用它管理真实项目，而不只是看到一个窗口或演示页面。**

它包含原规划中的管理 MVP，并把必要的打包、保存和检索验证放进开发批次中。**技术验证只是过程，不是这一阶段的最终交付。**

本阶段集中解决：**记下来、找得到、知道接着做什么。**程序运行和自动执行紧接着进入下一阶段，不在这一阶段混着开发。

# 1. 完成后，你实际能做什么？

用一个具体场景说明：

你想到“做一个对比几份报告差异的工具”，可以先写一句话收进想法箱，不必立即填写项目表单。

准备动手之前，搜索“报告”“对比”，发现以前已经做过一个相近工具。你能看到它解决什么问题、代码在哪里、是否经过验证，并打开对应目录或资料。

你决定继续改造它，于是记录：

> **上次完成：**已经能读取两份报告。  
> **当前阻塞：**还不能正确识别表格差异。  
> **下一步：**准备一组包含表格的测试文件。  
> **应该打开：**项目目录和相关对话。  
> **计划继续：**明天。

关闭软件、第二天重新打开后，这些内容仍然在。你不用重新翻找聊天记录，也不必重新回忆项目做到哪里。

**这就是第一阶段必须交付的完整使用闭环。**

另外，你可以登记只有想法、对话、文档或 GitHub 地址的项目，不要求它已经有代码，更不要求它能够运行。

# 2. 本阶段明确包含什么、不包含什么？

## 明确包含

| 能力 | 第一阶段做到什么程度 |
|---|---|
| **快速记录想法** | 输入一句话即可保存；以后可修改、设置复查日期、转成项目，并保留原始内容 |
| **手动登记项目** | 只强制填写名称；用途、类型、标签、状态等逐步补充；支持修改、归档和恢复 |
| **关联项目资料** | 一个项目可关联多个目录、文档、对话文件或网页链接；不移动原文件 |
| **普通检索和筛选** | 按名称、用途、功能描述、标签检索；按类型和状态筛选；支持中文短词和多个关键词 |
| **基本任务安排** | 一个项目可有多条任务，记录状态、简单优先级、计划日期和可选截止日期 |
| **恢复工作上下文** | 保存上次完成、当前阻塞、具体下一步、应打开的资料及工作记录 |
| **今日工作台** | 查看今天计划做的任务、近期安排、到期复查的想法，以及待重新安排的事项 |
| **本地数据保护** | 指定数据目录、可靠保存、备份、恢复，以及不含密钥的基本数据导出 |

有几个边界需要说清楚：

**项目登记要轻。**名称之外不强迫填写；没有截止日期也能创建任务。类型和标签允许自己添加，不做封闭分类。

**项目开发状态和成果可用程度分开。**例如“开发已完成，但现在需要修复”。本阶段的可用程度由你标注，软件不会因为发现代码目录就宣称“可运行”。

**中文搜索先做关键词匹配。**“采集”应能找到描述中含“数据采集”的项目；“网页 截图”应支持两个关键词共同筛选。第一阶段不承诺理解没有共同字面的同义表达。

**任务日期不等于执行计划。**设置“明天做”只影响工作安排，不会启动任何程序。

**资料以引用为主。**关联对话文件不等于解析、摘要或导入副本。脚本只能作为文本资料查看或打开所在目录，不能借“打开资料”动作偷偷执行。

## 明确不包含

| 暂不做 | 原因与后续位置 |
|---|---|
| 手动运行 Python 程序、运行配置、日志中心 | 放在紧接着的第二阶段，单独验证执行安全和异常处理 |
| 提醒后执行、自动执行、定时规则 | 在手动执行可靠之后增加 |
| 自动扫描目录、自动发现项目、批量审核 | 先确认手动管理流程真正好用，再减少录入工作 |
| 对话格式解析、自动摘要、AI 语义搜索 | 不让格式兼容、联网和隐私问题阻塞第一版 |
| 独立看板、完整日历、里程碑、任务依赖 | 第一阶段用任务列表和今日工作台完成基本安排 |
| 系统通知、托盘常驻、开机自启动 | 本阶段打开软件查看安排即可，不引入后台运行负担 |
| Outlook、iPhone、云同步、账号系统 | 不影响 Windows 本地闭环，后续另做 |

界面上也不预先摆出大量无法使用的菜单。**没有实现的执行中心、日历和导入审核，不作为灰色占位页面出现。**

# 3. 最终交付什么？能否双击启动？

**能。第一阶段的正式交付必须是在你的 Windows 电脑上可以双击启动的应用，而不是只有源码。**

推荐以以下形式交付：

| 交付物 | 你拿到后有什么用 |
|---|---|
| **Windows 应用压缩包** | 解压后双击 EXE 启动；首版不必制作安装向导，也不要求只有一个 EXE 文件 |
| **完整源码** | 后续交给 Codex、Claude Code 继续开发 |
| **简短使用说明** | 说明首次选择数据目录、登记、检索、记录下一步、备份和恢复 |
| **验收与交接记录** | 说明实际测试过什么、还有什么限制、下一阶段从哪里继续 |

应用应满足：

**普通用户权限可以使用；不要求你为了运行管理器安装 Python 或开发工具；不依赖 AI 服务。**这些必须在目标 Windows 环境实际验证，不能仅以“开发机上能运行”为依据。

数据与程序分开放。首次启动时，你选择管理数据目录；以后更新或换一个程序解压目录，不应该丢失项目资料。

需要特别区分：

> **工作台备份保存的是项目档案、想法、任务、工作记录和关联信息，不是自动备份所有项目源码和外部对话原文件。**

第一阶段以引用方式关联这些外部资料，因此它们仍需要保留在原处。

# 4. 你怎样操作，才能确认真的可用？

建议使用少量可重录的样例完成下面的验收。**不必真的等到第二天，也不必一次录入几十个项目。**

| 步骤 | 你实际做什么 | 什么结果才算通过 |
|---|---|---|
| **① 启动和保存** | 解压，双击启动，选择数据目录，记录一句想法；关闭再打开 | 不用开发工具启动；想法仍然存在 |
| **② 登记不同形态的项目** | 登记一个有本地代码的项目、一个只有对话的项目、一个只有名称和用途的项目 | 三种都能保存；没有代码的项目不会被要求补目录，也不会出现运行按钮 |
| **③ 验证中文查找** | 给测试项目写入“网页数据采集”等用途，分别搜索“采集”和“网页 采集” | 能找到预期项目，并能看懂为什么匹配；修改用途或标签后搜索结果同步更新 |
| **④ 安排下一步** | 建一个任务，计划日期设为今天，不填截止日期；再建一个明天的任务 | 今天和近期安排显示正确；不强制截止日期，也不会执行程序 |
| **⑤ 模拟下次继续工作** | 写下完成事项、阻塞和下一步，关联要打开的资料；关闭软件后重新打开 | 能从首页找到项目，看到上下文，并打开对应资料 |
| **⑥ 验证修改与失效处理** | 修改项目名称，归档后恢复；把一个测试来源改成不存在的路径 | 修改被保留；归档可恢复；失效路径明确显示，但项目档案不丢失 |
| **⑦ 验证备份恢复** | 创建备份，恢复到另一个空的数据目录 | 项目、想法、任务、工作记录和关联信息一致；恢复不覆盖原数据目录 |
| **⑧ 验证程序与数据分离** | 把同一版本解压到另一个程序目录，启动后选择原数据目录 | 原有内容仍可使用，不需要重新录入 |

“下次继续工作”的验收，不是只看有没有一个“下一步”字段，而是看你能否根据它直接开始做事。例如：

“继续优化”不够具体；“检查第二页请求参数，并用两页样例验证”才有实际帮助。

备份恢复也不能只验收“生成了一个备份文件”，必须真的恢复并核对内容。

# 5. 拆成六个可分别验证的开发批次

**每批都交付一个更新后的可双击版本和验证记录。前一批没有通过，不继续堆后面的界面。**

| 批次 | 开发内容 | 独立验收点 |
|---|---|---|
| **第 1 批：可启动、可保存的最小应用** | Windows 打包、选择数据目录、记录和修改一句想法、重启读取 | 双击能启动；输入真实内容后关闭重开，内容不丢。这一批就不能只是静态窗口 |
| **第 2 批：真实项目档案** | 项目新增、修改、归档和恢复；用途、开放类型与标签；关联多个来源；失效路径提示 | 能登记代码项目、对话项目和不完整项目，并打开有效资料 |
| **第 3 批：找回项目与整理想法** | 中文关键词检索、筛选；想法复查日期；想法转项目并保留来源 | 能找到预先准备的中文样例；转换不丢原文，也不重复生成项目 |
| **第 4 批：记录工作上下文** | 基本任务、当前下一步、工作记录、阻塞点和相关资料 | 一个项目可以有多个任务，但“当前下一步”只有一个明确来源；重启后可恢复工作 |
| **第 5 批：今日安排** | 今天、近期、待复查、待重新安排；计划日期和截止日期的区别 | 同一任务在首页和项目详情中一致；改一处另一处更新，不维护两份内容 |
| **第 6 批：数据保护与交付验收** | 一致性备份、恢复、基本导出、错误提示、完整使用说明；跑通所有验收流程 | 备份实际可恢复；更换程序目录不丢数据；目标 Windows 上完成真实操作验收 |

前五批先用测试数据或少量可重录的资料。**备份恢复通过后，再开始较大规模录入真实项目。**

开发过程中有两条限制：

**“下一步”直接关联一条任务。**不分别保存一份首页下一步、一份项目下一步和一份任务描述，避免互相矛盾。

**任务列表与今日工作台共用同一份任务数据。**后续增加看板和日历时，只增加视图，不重建任务体系。

# 6. 哪些事情确实需要你决定？

真正需要你参与的只有两个使用层面的事项，**现在不必为此暂停规划**。

| 需要你决定或提供的事项 | 推荐处理 |
|---|---|
| **管理数据保存在哪里** | 首次启动时选择一个普通本地文件夹，与程序目录、项目源码目录分开；首版不使用网络共享或正在同步的文件夹作为活动数据库位置 |
| **用哪些项目完成真实试用** | 选少量有代表性的样例：一个本地 Python 项目、一个搁置项目、一个只有对话的项目和一个新想法；不需要交出全部项目或完整聊天历史 |

真实资料可以由你在本机试用时自行录入。开发和自动测试先使用虚构样例，**选择试用项目不等于授权 AI 扫描、读取或上传它们的全部内容。**

其他技术细节直接采用以下推荐，不再交给你做选择题：

| 技术或交互问题 | 推荐 |
|---|---|
| 技术栈 | 沿用 **C#/.NET 10 + WPF + SQLite** |
| 交付方式 | 先做自包含 Windows 应用包，解压双击启动，不先做复杂安装器 |
| 页面结构 | 今日工作台、项目库、项目详情、想法收集、设置；不单独建设复杂任务模块 |
| 保存方式 | 数据库存管理信息；目录、文档和对话默认只保存引用 |
| 搜索方式 | 本地普通关键词检索，不接 AI，不建设向量数据库 |
| 网络与隐私 | 无默认上传、遥测或在线摘要；打开网页链接由你主动点击 |
| 应用退出 | 关闭即退出；不承诺退出后提醒，也不增加后台服务 |
| 数据安全 | 备份恢复是阶段完成条件，不作为以后再补的功能 |

## 第一阶段的完成标准

**它不是“有了项目列表和几个按钮”就算完成。**

只有当你能够在自己的 Windows 电脑上，使用真实或代表性资料完成：

> **记录想法 → 登记项目 → 中文搜索找回 → 安排具体下一步 → 关闭重开后继续工作 → 备份并成功恢复**

这个阶段才算交付。

到这里，你得到的是一个可以开始替代零散笔记和记忆的小工具；下一阶段再让它安全地运行已有程序。
